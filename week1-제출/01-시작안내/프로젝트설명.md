# 1조 SSD 프로젝트 — 예상손익 LLM Wiki

> 더미 예상손익 자료를 **AI와 팀원이 다시 쓸 수 있는 팀 지식**으로 정리하는 프로젝트.
> AI에게 바로 코딩을 시키지 않고, **근거 있는 자료를 먼저 갖춘 뒤** AI가 그 위에서 일하게 한다.

---

## 한눈에 보기

| 항목 | 내용 |
|---|---|
| **무엇을** | 예상손익 지식을 LLM Wiki로 정리 |
| **왜** | 계획 대비 실적 보고서를 AI가 **근거 있게** 다시 만들도록 |
| **어떻게** | 자료 찾기 → Wiki 가공 → 검증·제출 |
| **원칙** | 가공은 AI, **최종 확인·승인은 사람** |
| **상태** | 검증 통과(오류 0·경고 0), 전 문서 확인 완료 |

---

## 작업 흐름

```
질문 만들기 → 자료 찾기 → 원문 확인 → 필요한 내용만 정리
→ AI에게 전달 → 팀 Wiki로 저장 → 다른 팀원이 다시 확인
```

**1단계 · 자료 찾기**
넓은 요청을 개발 질문 5개로 쪼갠다 — 누가 쓰는가 / 입력·형식 / 업무 규칙 / 결과물 형태 / AI가 정하면 안 되는 것.
자료는 신뢰도 순서로 읽고, 확인 전에는 모두 '후보'로 표시한다. → `02-질문과-출처/`

**2단계 · Wiki 가공**
원문은 `vault/raw/`에 `SRC-날짜-번호`로 **원본 그대로** 보관하고, 가공본만 `vault/wiki/`에 만든다.
모든 문서는 같은 서식(한 줄 요약 · 근거 위치 · 사용처 · 확인 상태)으로 쓰고 목차·기록으로 연결한다.

**3단계 · 검증과 제출**
`wiki_lint.py`로 링크·속성·출처·고립 문서를 자동 점검하고, 통과하면 `week1-제출/`로 제출한다.

## 폴더 구조

```
01-SSD/
├── CLAUDE.md              AI가 따르는 작성·검증 규칙
├── vault/                 LLM Wiki (프로젝트 지식)
│   ├── raw/                 원문 원본 (수정 금지)
│   └── wiki/                가공 지식 (index·log·sources·concepts·projects)
├── scripts/wiki_lint.py   자동 검증 도구
├── templates/             노트 서식
└── week1-제출/            제출물 (시작안내 · 질문과출처 · 결과와제출)
```

**LLM Wiki 3층**

| 층 | 위치 | 역할 |
|---|---|---|
| 규칙 | `CLAUDE.md` | AI가 매번 따르는 운영 규칙 |
| 지식 | `vault/wiki/` | AI가 요약·비교·연결하는 가공 지식 |
| 원문 | `vault/raw/` | 원본을 수정하지 않고 보관 |

## AI 작업 규칙

- 입력 원본을 수정하지 않는다.
- 빈 값을 0으로 추측하지 않는다.
- 모든 계산·주장은 원문(SRC 번호)으로 추적할 수 있어야 한다.
- 계획이 0이면 차이율을 임의 계산하지 않고 '확인 필요'로 표시한다.
- 실제 기업 수치·식별정보를 요청·저장하지 않는다. (SAP·외부 연결·자동 승인 금지)
- **가공은 AI가, 최종 확인·승인은 사람이 한다.**

> 원문: `../../CLAUDE.md`

## 상태 생애주기 (문서 status)

vault의 모든 wiki 문서는 `status` 속성을 가지며 세 단계로 관리된다.

| status | 뜻 | 승격 주체·조건 |
|---|---|---|
| `needs-review` | 초안. 작성됐으나 독립 확인 전 | 작성자가 부여 |
| `reviewed` | 작성자가 아닌 팀원이 근거·사실을 확인함 | 조장·조원 중 **작성/확인 안 한 사람**이 확인 후 승격 |
| `active` | 목차·로그 등 상시 운영 문서 | `index.md`·`log.md` 등 |

- 승격 기록은 `vault/wiki/log.md`에 `promote` 항목으로 남긴다.
- 허용 값은 `wiki_lint.py`가 강제한다(그 외 값은 오류).

## 사람 승인 게이트 (한계 포함)

- **사람 승인이 필요한 것**: 최종 보고서 승인 · 차이 원인 판정 · 차이 임계값 확정 · 민감정보·실제 손익 처리.
- **현재 막는 방식**: ① `CLAUDE.md` 금지 규칙, ② 지식의 `needs-review → reviewed` 사람 확인 단계, ③ 보고서의 "사람 확인 목록".
- **한계(정직)**: 위 셋은 규칙·절차이지 **기술적 강제 장치가 아니다.** AI의 자동 승인을 코드로 차단하는 게이트는 아직 없으므로, **사람이 반드시 최종 확인**해야 한다.
