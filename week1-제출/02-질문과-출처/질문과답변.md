# 질문과 답변 · 예상손익

넓은 요청("예상손익 자동화 자료 찾아줘")을 바로 검색하지 않고, **개발에 꼭 필요한 5개 질문**으로 쪼갠 뒤 각 질문에 답한다.
확인 전 자료는 모두 **후보**로 표시하고, 확인된 답에는 근거(SRC 번호)를 붙인다.

---

## Q1. 누가 쓰는가?

**답변.** 이 결과물은 **PM(프로젝트 관리자)과 재무 담당자**가 사용한다. 이들은 매월 **법인·프로젝트 단위로 계획 대비 실적**이 얼마나 벌어졌는지를 빠르게 확인하고, 그 결과를 보고와 의사결정의 근거로 삼는다.

따라서 결과물은 숫자를 나열하는 데 그치지 않고, **어디서 얼마나 차이가 났는지**와 **사람이 확인·판단해야 할 지점**이 함께 보여야 한다. 회계 비전문가인 팀원도 표만 보고 흐름을 이해할 수 있어야 한다.

- **확인 상태:** 후보 (실제 사용자·용도는 담당자 확인 필요)

---

## Q2. 어떤 입력·형식인가?

**답변.** 입력은 **CSV 파일 1개**이며, 다음 6개 열을 가진다.

| 열 | 의미 | 형식 |
|---|---|---|
| `month` | 기준월 | `YYYY-MM` (예: 2026-08) |
| `company` | 법인명 | 문자열 |
| `project_id` | 프로젝트 번호 | 문자열 (예: P-101) |
| `category` | 계정 구분 | `revenue` / `cost` / `expense` 중 하나 |
| `plan` | 계획 금액 | 정수 |
| `actual` | 실적 금액 | 정수 |

예시 행:

```
2026-08,Demo Alpha,P-101,revenue,120000,115000
2026-08,Demo Beta,P-202,cost,54000,56000
```

형식 규칙은 두 가지다. **빈 값을 0으로 추측하지 않으며**, 허용된 `category`(revenue/cost/expense) 외의 값은 오류로 표시한다.

- **확인 상태:** 확인됨 (근거: SRC-20260813-001 · `vault/wiki/sources/SRC-20260813-001-pnl-input-spec.md`)

## Q3. 업무 규칙은?

**답변.** 계획과 실적으로 차이와 차이율을 계산하는 규칙은 다음과 같다.

1. **차이(variance) = 실적(actual) − 계획(plan)** — 부호는 그대로 유지하며, 음수 조정도 임의로 바꾸지 않는다.
2. **차이율(%) = (차이 ÷ 계획) × 100**
3. **계획(plan)이 0이면 차이율을 계산하지 않고 '확인 필요'로 표시한다.** (0으로 나눌 수 없으므로 임의 계산 금지)

해석 시 주의할 점도 있다.
- `revenue`(수익): 차이가 **양수 = 계획 초과 달성**
- `cost`·`expense`(비용): 차이가 **양수 = 예산 초과(주의 신호)**

즉 같은 '양수'라도 계정 구분에 따라 좋은 신호일 수도, 나쁜 신호일 수도 있어 **부호 해석에 주의**해야 한다. 최종 해석과 승인은 사람이 한다.

- **확인 상태:** 확인됨 (근거: SRC-20260813-002 · `vault/wiki/sources/SRC-20260813-002-variance-rule.md`)

## Q4. 결과물 형태는?

**답변.** 결과물은 **Markdown 보고서 1개**이며, `outputs/` 폴더에만 저장한다. 보고서는 다음을 담는다.

1. **법인·프로젝트별 표** — 계획 / 실적 / 차이 / 차이율
2. **입력 이슈** — 누락, 중복, 숫자 형식 오류, `plan = 0` 항목을 **행 번호와 함께** 표시
3. **사람 확인 목록** — 합계·부호, 차이가 큰 항목의 실제 원인, 가정·누락값, 최종 승인 상태

핵심은 **모든 수치를 입력 행으로 추적할 수 있어야** 한다는 점이다. 계산 결과만 있고 근거가 없으면 안 된다.

- **확인 상태:** 후보 (기대 형태 참조: `samples/expected/forecast-pnl-report.md`)

## Q5. AI가 결정하면 안 되는 것은?

**답변.** AI는 계산·정리·초안 작성까지 맡되, 다음은 **사람이 결정**한다.

- **최종 승인** — 보고서를 확정·승인하는 판단
- **차이 원인 판정** — 왜 그런 차이가 났는지에 대한 해석
- **'차이가 크다'의 임계값 기준** — 예: ±10%를 크다고 볼지 (근거 없이 정하지 않음)
- **민감정보·실제 손익 처리** — 실제 기업 수치·식별정보는 요청·저장하지 않음
- **외부 연결·자동 승인** — SAP 등 외부 시스템 연결이나 자동 승인 금지

이유는 이들이 **근거가 없거나 책임이 따르는 판단**이기 때문이다. AI가 임의로 채우면 신뢰할 수 없으므로, 이런 항목은 '확인 필요'로 남겨 사람에게 넘긴다.

- **확인 상태:** 후보 (프로젝트 규칙 근거: `../../CLAUDE.md`)

## AI에게 먼저 받을 것 (답이 아니라 조사 계획)

자료를 바로 받기 전에, AI에게 **조사 계획**부터 요청한다.

- 필요 자료 / 찾을 위치 / 확인할 사람 / 날짜·버전 / 사용처

## 확정된 결정 (2026-08-14)

- `actual` 빈 값·0·음수 → **데이터 오류**로 판정, 계산 제외 후 행 번호·사유 표시 (실적은 항상 0보다 크다는 전제)
- 차이 임계값 → **달성율 ±10%**, 색상은 유리=파랑 / 불리=빨강 (비용은 −가 파랑)

## 남은 확인 필요 (사람 결정)

- 신규 착수월 등 실적이 정상적으로 0인 예외가 있는지 확인
