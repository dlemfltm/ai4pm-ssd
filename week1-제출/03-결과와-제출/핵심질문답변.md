# 핵심 질문 5개 답변 + 출처 · 예상손익

개발 질문 5개 각각에 **확인된 내용(근거) / 우리의 판단 / 확인 필요**를 단다.
원칙: **모르는 건 비워둔다.** 근거 없이 채우면 그 순간 지어낸 것이 된다.

---

## Q1. 누가 쓰는가?

### 확인된 내용

- 입력·규칙 자료(SRC-20260813-001·002)에는 **사용자가 명시돼 있지 않다.**
- 프로젝트 설정 문서(`CLAUDE.md`, `README.md`)가 "PM·재무 담당자"를 언급한다. (근거: `../../CLAUDE.md`)

### 우리의 판단

- PM·재무 담당자가 월별 계획 대비 실적을 점검하는 용도로 **가정**한다.

### 확인 필요

- **실제 사용자·사용 빈도·의사결정 연계는 미확인.** 담당자 확인 필요.

---

## Q2. 어떤 입력·형식인가?

### 확인된 내용

- 필수 6열 `month, company, project_id, category, plan, actual`, `category`는 revenue/cost/expense. (근거: `SRC-20260813-001` → [입력스키마](../../vault/wiki/concepts/입력스키마.md))

### 우리의 판단

- 열 순서가 바뀌어도 **열 이름 기준**으로 처리하고, 허용 category 외 값은 오류로 표시한다.

### 확인 필요

- `actual` 빈 값 처리 방식 **미정** (0으로 채우지 않음).

---

## Q3. 업무 규칙은?

### 확인된 내용

- 차이 = 실적 − 계획, 차이율 = 차이 ÷ 계획 × 100, plan=0이면 "확인 필요". (근거: `SRC-20260813-002`)
- 유리/불리는 수익·비용에 따라 갈리고, 회사는 **범위를 벗어난 차이만** 설명한다. (근거: `SRC-20260814-103` OpenStax → [차이율](../../vault/wiki/concepts/차이율.md)·[차이부호해석](../../vault/wiki/concepts/차이부호해석.md)·[차이임계값](../../vault/wiki/concepts/차이임계값.md))

### 우리의 판단

- 위 공식·부호 규칙을 확정 적용한다. 임계값은 "범위 밖만 원인 규명" 방식을 채택한다.

### 확인 필요

- **임계값 구체 수치(예: ±10%)는 미정.** 담당자 결정 필요.

---

## Q4. 결과물 형태는?

### 확인된 내용

- Markdown 보고서 1개: 법인·프로젝트별 표(계획/실적/차이/차이율) + 입력 이슈 + 사람 확인 목록. (근거: 기대 형태 `samples/expected/forecast-pnl-report.md`, 대장 SRC-20260813-004 · 내부 참조)

### 우리의 판단

- 결과는 `outputs/`에만 저장하고, **모든 수치는 입력 행으로 추적** 가능해야 한다.

### 확인 필요

- 보고서 세부 서식(정렬·합계 표기)은 담당자 확인 여지.

---

## Q5. AI가 결정하면 안 되는 것은?

### 확인된 내용

- 프로젝트 규칙상 **실제 손익·계정정보 사용, SAP 연결, 자동 승인, 투자 판단 금지.** (근거: `../../CLAUDE.md`, 대장 SRC-20260813-003)

### 우리의 판단

- 최종 승인·차이 원인 판정·임계값 확정·민감정보 처리는 **사람**이 한다. AI는 검사·계산·초안까지. (근거: [근거추적검증](../../vault/wiki/concepts/근거추적검증.md))

### 확인 필요

- **자동화 허용 경계**(어디까지 AI가 하고 어디부터 사람 승인인지)의 세부 기준은 담당자 승인 필요.
